## 10. Step 8: bundles, signing and UI (added 2026-11-25; drift SAME before and after)

**Accepted upload formats** (`POST /api/brain`, `server/app.py:165`):

| Upload | Accepted? | How it is checked |
|---|---|---|
| Bare `.onnx` | **Yes** (up to MAX_BYTES) | brain loader checks: operators, shapes, time limit. Stored as kind `onnx`, so no recipe, scores or Verified |
| `bundle.tar` (unsigned) | **Yes** | detected by tar magic (`ustar` at byte 257), not by file name; full `read_bundle()` checks |
| `*.signed.tar` | **Yes** (not required) | same checks, plus an Ed25519 check of `signature.json` over `manifest.json`; author trusted on first use |
| Bundle refused when | | wrong version, a file missing / extra / changed (size or sha256), links or folders, more than 12 members, more than 20 MB, a name outside the allowed list, a bad brain, a bad config, names that differ, a bad signature |

**Manifest (`manifest.json`, schema `data/schemas/bundle-manifest.schema.json`):** `format`
("minotaurus-brain-bundle"), `version` (1), `brain_id` (sha256 of brain.onnx), `name`, `method`,
`files[]` {name, size, sha256}. Allowed members: manifest.json, brain.onnx, config.json, and
optionally scores.json, fixed_levels.json, test_stats.json, metrics.jsonl, training.png, plus
signature.json. Checkpoints are never included.

**CLI:** `pack <run_dir> [--out]`, `sign <tar> [--key] [--out]`, `keygen [--out]`. **There is no
`verify` command:** verification is the server's replay (`verify.py`, `POST /api/brains/{id}/verify`).
